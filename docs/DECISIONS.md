# Inlay — decisions (ADR log)

Short entries, newest at the bottom. Each: context, decision, consequence. Deviations from `docs/BRIEF.md` are proposed to the product owner before being logged as accepted.

## ADR-0001 — Read view renders client-side and replaces the page in place (2026-11-05)
The shell page at `mdview://<docId>/` embeds the document source as JSON; the read-view runtime renders it with md-render (browser build) and calls `document.open()/write()/close()` so document `<script>`/`<style>` run in page order like a navigated page and relative URLs resolve against the document folder. No fetch endpoint for the source exists, so `connect-src 'none'` stays literal. Refresh pushes new source via `evaluateJavaScript` (fallback `reload()`), scroll restored via `sessionStorage`. Fallback if `document.write` misbehaves in WKWebView: native renders through the JSC bundle and the webview navigates to the result.

## ADR-0002 — Both webviews load through the `mdview://` scheme handler (2026-11-05)
The editor webview also loads its page and document assets through the handler and traversal guard; only it gets the `WKScriptMessageHandlerWithReply` bridge. Web code receives the document base URL from `Host.openDocument`, never a hardcoded scheme, so Tauri can later map it to `http://mdview.localhost/…`. The `__inlay/` path prefix is reserved for runtime assets and shadows a same-named folder in the document directory.

## ADR-0003 — Byte preservation model (2026-11-05)
Swift keeps the original `Data`; the web core works on the losslessly decoded UTF-8 string plus `{bom, eol}`. All web offsets are UTF-16 string indices (remark positions), never bytes; bytes are produced only by re-encoding. Source mode first tries CodeMirror `lineSeparator` = dominant EOL so stray `\r`/`\n` survive as highlighted characters; if the mixed-EOL prototype shows glitches, fall back to normalized `\n` plus a per-line EOL table maintained through change sets. Non-UTF-8 files open read-only with a banner.

## ADR-0004 — WYSIWYG block model with per-block style sniffing (2026-11-05)
md-render's parse gives top-level blocks with offsets and inter-block gaps. Each block is round-tripped through Milkdown's parser + serializer with sniffed style options (bullet, emphasis/strong char, fence style, list indent, heading style, EOL) applied via a per-block remark instance, because `remarkStringifyOptionsCtx` is read once at editor creation. Mismatch ⇒ raw island atom holding the exact slice. Save: unchanged node ⇒ original slice; changed/new ⇒ serialized; islands ⇒ source attr; gaps and trailing newline preserved. remark versions are pinned shared between md-render and Milkdown and an mdast-equality test guards against phantom islands.

## ADR-0005 — Save pulls live editor content; native mirror only for crashes (2026-11-05)
`NSDocument.save(to:ofType:for:completionHandler:)` first requests content from the live editor (`callAsyncJavaScript`), then calls super; `data(ofType:)` returns that content. Autosave, Duplicate, Save As and Versions go through the same override. A debounced native last-known-good mirror is used only when the web content process has terminated or times out, and the user is warned. This keeps the brief's "never from a cached copy" while avoiding data loss on a WebContent crash.

## ADR-0006 — JavaScriptCore bundle constraints (2026-11-05)
esbuild IIFE, `platform: neutral`, no DOM. Shiki runs with `createHighlighterCoreSync` and the JavaScript regex engine (no WebAssembly dependence) over a curated grammar set, with a conservative regex target because the extension runs on the user's OS JavaScriptCore (macOS 14+). KaTeX via `renderToString`. Small polyfills (`TextEncoder`, `queueMicrotask`, `console`). `assetLoader` option lets Swift supply bytes for `inlineAssets`. The extension keeps one warm `JSContext`. A parity test requires identical `static` HTML from the browser and JSC builds for every fixture.

## ADR-0007 — Read view CSP, trust and network policy (2026-11-05)
Isolation: non-persistent store, no script message handlers, `WKUIDelegate` refuses `window.open`, navigation policy sends `http(s)` to the default browser and refuses `file:`, scheme handler `realpath`s every path and serves only the document folder. CSP is a response header (persists across `document.open`). With CDN = cdnjs.cloudflare.com, cdn.jsdelivr.net, unpkg.com (brief amendment): `default-src 'none'; script-src 'unsafe-inline' mdview: CDN; style-src 'unsafe-inline' mdview: CDN; font-src mdview: data: CDN; img-src mdview: data: blob: https:; media-src mdview: data: blob:; connect-src 'none'; frame-src 'none'; child-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`. Remote images are allowed by default (product owner decision 2026-11-05). Untrusted (quarantined, not yet trusted) documents get nonce-only `script-src` and static rendering. "Allow network" (per document, remembered per path) widens `connect-src`, `script-src`, `style-src`, `font-src` to `https:`. Trust is stored in app preferences keyed by path + quarantine xattr value; the file is never modified.

## ADR-0008 — Known-library URL rewriting (2026-11-05, brief amendment)
A rehype step rewrites Chart.js, ECharts, D3, Mermaid and KaTeX URLs on the three allowlisted CDNs (`<script src>` and `<link href>`, versioned or not) to bundled copies under a `vendorBaseURL` option (app: `mdview://<docId>/__inlay/vendor/…`; Quick Look Tier 2: `cid:` attachments). Rewrite only when the requested major version matches the bundled major or is unspecified; otherwise the CDN URL is left intact (still allowed by CSP). Vendored copies are shipped dependencies: license-checked and listed in THIRD_PARTY_NOTICES. The mapping table is data with per-URL-form unit tests.

## ADR-0009 — Custom-scheme origins (2026-11-05, brief amendment)
No web code assumes `https:`. `isTrustedOrigin(origin, baseURL)` in `host-api` handles `mdview://<docId>`, `http://mdview.localhost`, and WebKit's `"null"` origin; every `message` listener uses it. Unit-tested.

## ADR-0010 — No web→native channel from the Read view (2026-11-05)
Position for mode switching is pulled by native with `evaluateJavaScript`. Split-mode scroll sync is source→read only in v1; read→source would need a web→native path and can be added later through a bounded URL endpoint if wanted.

## ADR-0011 — `data-source-line` on raw HTML blocks (2026-11-05)
`rehype-raw` reparses raw HTML and drops positions. md-render injects `data-source-line` into the first start tag of each top-level raw HTML block before `rehype-raw` (skipping `<script>`, `<style>`, comments) so Split sync and mode switching stay accurate around embedded HTML.

## ADR-0012 — App is not App-Sandboxed (2026-11-05)
Distribution is Developer ID only (Mac App Store is a non-goal). Prompt-free access to sibling assets in the document folder is the blocker for sandboxing; hardened runtime stays on, which is all notarization needs. The Quick Look extension is sandboxed by the system; the M0 spike decides whether a scoped read-only exception is needed for sibling images.

## ADR-0013 — File change detection via NSFilePresenter first (2026-11-05)
NSDocument already conforms to `NSFilePresenter`; use `presentedItemDidChange` first, add a `DispatchSource` vnode watcher only if uncoordinated writes are missed, and deduplicate notifications by content hash.

## ADR-0014 — Tooling and workflow (2026-11-05)
pnpm workspace; Vite per page package; esbuild for the JSC IIFE; Vitest (node + jsdom); Playwright Chromium + WebKit on the Linux CI job only (Playwright WebKit is a trunk build, not WKWebView; in-process XCTest app tests are the real-WKWebView evidence); Biome for lint/format; XcodeGen; XCTest without XCUITest. Swift 6 language mode with main-actor default isolation on app/extension targets, deployment target macOS 14, no Xcode-27-only features. CI macOS job runs on `macos-26` with Xcode 26.3. Git: branch renamed `master`→`main` before the first commit; M0 lands on `main`; later milestones use branches + PRs merged on the product owner's "go"; DCO sign-off (`-s`), Conventional Commits.

## ADR-0015 — License policy scope (2026-11-05, product owner)
The MIT/BSD/Apache-2.0/ISC allowlist applies to shipped code (app and extension bundles incl. vendored libraries, Swift packages, fonts). The GPL/AGPL/LGPL deny-list applies to the entire dependency tree including dev tools and fails CI. SIL OFL 1.1 is accepted for font files only (KaTeX fonts) and listed in THIRD_PARTY_NOTICES. `dompurify` (Apache-2.0 OR MPL-2.0) is taken under Apache-2.0.

## ADR-0016 — Product defaults chosen where the brief is silent (2026-11-05)
Front matter hidden in Read view (its `title` feeds the window title), island card in WYSIWYG. Scripts run by default for non-quarantined documents. Assets outside the document folder are not served. Large-document safety net: above ~50k lines / 5 MB open in Source mode with a one-click switch (the 10k-line fixture stays in WYSIWYG). Quick Look caps inlined image sizes and truncates very large documents with a note. System fonts for UI/body; only KaTeX fonts are bundled.

## ADR-0017 — Quick Look spike status after M0 (2026-11-05)
The M0 stub extension (`InlayQuickLook`) is the spike: its data-based preview prints whether JavaScript ran, whether a sibling file (`assets/sample.svg`) was readable inside the sandbox, and whether a `cid:` attachment resolved. Verified so far: the extension builds, is embedded, `pluginkit` lists it as enabled for `com.apple.quicklook.preview`, and LaunchServices knows `live.inlay.Inlay.QuickLook` for `net.daringfireball.markdown`. Not yet verified: `qlmanage -p` never launched the extension from the CLI (no log line from the provider), `qlmanage -p -o` crashes inside qlmanage, and screen capture is unavailable in this session, so the three results must be read in Finder (select a fixture, press Space). Verdict and M4 tier scope stay open until then; if scripts do not run, see risk 1 in the plan (view-based extension vs static-only).

## ADR-0018 — Quick Look spike verdict (2026-11-05, verified in Finder by the product owner)
Result of the M0 spike with the stub extension (debug build, ad-hoc signed, sandboxed with `files.user-selected.read-only`): (1) **JavaScript runs** in a data-based `QLPreviewReply` HTML preview, so Tier 2 (scripts opt-in, Mermaid) is feasible as the brief describes and no WKWebView is needed in the extension. (2) **Sibling files are not readable**: `assets/sample.svg` next to the previewed file could not be read inside the sandbox, so Tier 1 image inlining needs a scoped read-only sandbox exception (to be tried first in M4: a temporary-exception entitlement limited to read-only; if rejected or unavailable, images outside the file itself show a placeholder). (3) **`cid:` attachments resolve**, so KaTeX fonts, vendored libraries and (if the brief's data-URI approach proves too large) images can ship as `QLPreviewReplyAttachment`s. Note for testing: QLMarkdown, when installed, takes over Markdown previews; the system picks one extension per type, so verification needs other Markdown Quick Look extensions paused.

## ADR-0019 — App icon rendered from SVG masters through CoreSVG (2026-11-05)
The app icon, mark and glyphs live as SVG masters in `design/icon/`; `scripts/render-icons.sh` renders the Xcode `AppIcon.appiconset` (16 to 1024 px, with a simplified cut for 16 and 32 px) and the web favicons, and the PNGs are committed so a checkout builds without the script. Rendering uses a 30-line AppKit program (`scripts/icons/svg2png.swift`, NSImage + CoreSVG on a transparent bitmap) instead of a Node or Homebrew dependency: `rsvg-convert` is not installed by default, ImageMagick's built-in SVG renderer drops gradients, and `qlmanage` thumbnails are flattened on white. CoreSVG does not support `feMerge`, so the icon's drop shadow is a separate blurred rectangle. The catalog is a plain `appiconset` rather than a macOS 26 `.icon` bundle because the deployment target is macOS 14; Liquid Glass wraps the legacy icon on newer systems, and a `.icon` variant can be added later without changing the masters.

## ADR-0020 — Licensing of vendored library bundles; recursive license scan (2026-11-05)
`pnpm licenses list` was only scanning the root importer in M0 (0 shipped packages); the check now runs with `-r` and covers every workspace package's production dependencies (239 shipped after M1 adds the pipeline and vendored libraries). Two libraries compiled into prebuilt bundles are not on the allowlist: `robust-predicates` (Unlicense, inside `d3.min.js` via d3-delaunay) and `elkjs` (`EPL-2.0 OR GPL-3.0-or-later`, taken under EPL-2.0, inside `mermaid.min.js` 12.x). Both are recorded in `scripts/license-policy.json` as exceptions with `"status": "pending"`: the check passes but prints them loudly until the product owner accepts the licenses or we stop vendoring the affected library (D3 and Mermaid CDN URLs would then stay untouched and need network). `khroma` ships an MIT license file but no `license` field; a `licenseOverrides` entry corrects it. KaTeX fonts are listed under the approved OFL-1.1 fonts exception.

## ADR-0021 — md-render output contract and highlighting strategy (2026-11-05)
`render()` returns body-only HTML; the embedding page (Read view, Quick Look, export) owns `<html data-theme>` and includes `THEME_CSS`, so one theme follows `prefers-color-scheme` unless overridden. Mode behaviour: `full` keeps the document verbatim (optionally stripping scripts and inline handlers with `allowScripts: false`); `static` and `sanitized` replace every `<script>` with a placeholder and sanitize with a schema that keeps SVG, MathML, inline styles, classes, ids and `data-*` (no clobber prefix, so footnote links work); `sanitized` also drops `<style>`. KaTeX and Shiki run after sanitizing because their output is ours. Highlighting is pluggable (`CodeHighlighter`): the JavaScriptCore build highlights synchronously with 40 bundled grammars (4.3 MB IIFE); the browser first paints unhighlighted `<pre><code class="language-x">` for an instant first render, then read-view lazily imports only the grammars in `meta.codeLanguages` and upgrades the blocks in place with `highlightToHtml`. Both builds use the JavaScript regex engine with `target: 'ES2018', forgiving: true` so output is byte-identical (the parity test compares every fixture in every mode). Shiki emits dual-theme CSS variables; `light-dark()` is avoided because macOS 14's WebKit predates it. Raw HTML blocks get `data-source-line` injected as the first attribute of their start tag (ADR-0011); `integrity`/`crossorigin` are dropped from rewritten CDN tags because the hashes were computed for the CDN file.

## ADR-0022 — Read view runtime: in-place page replacement, reload-based refresh, dev view route (2026-11-05)
The runtime renders the embedded source and replaces the shell with `document.open()/write()/close()` as planned in ADR-0001; Playwright (Chromium, WebKit) and the WKWebView XCTest confirm the CSP response header survives the replacement and that document `<style>`/`<script>` run at page level. **Refresh reloads instead of re-writing:** `inlayReadView.refresh()` stores the top source line in `sessionStorage` and calls `location.reload()`; the scheme handler re-embeds the live source and the runtime restores the position by source line (falling back to pixels). A second `document.write` in the same Window would leave the previous render's timers and globals alive, so a reload is both simpler and safer; Split mode (M2) can revisit this if reload latency matters. Runtime assets (vendor copies, lazy grammars) resolve from Vite's `BASE_URL` (`/__inlay/`, the reserved prefix of ADR-0002) against the page URL, so no scheme is hardcoded: `mdview://<docId>/__inlay/…` in the app, `http://localhost/__inlay/…` in dev. The browser dev server mirrors the app faithfully: `/__fixtures/view/<file>.md` serves the same shell with the fixture embedded and the same CSP (built by `packages/read-view/src/csp.ts`, kept in sync with the Swift builder by unit tests on both sides), and other paths under `/__fixtures/view/` serve files from the fixture folder behind the same traversal guard, so Playwright exercises the real policy. The dev bar is part of the rendered page only when the payload carries `dev`.

## ADR-0023 — Mermaid via the vendored UMD bundle, re-rendered on theme change (2026-11-05)
In `full` mode md-render emits `<pre class="mermaid">source</pre>`; the runtime injects the vendored `mermaid.min.js` (the same file CDN rewriting points documents at, so one copy serves both) only when the document has such blocks, then calls `mermaid.run` per node with `securityLevel: 'strict'`. Each node keeps its source in `data-inlay-mermaid-src` so diagrams re-render when `setTheme` or the system appearance changes (Mermaid bakes the theme into the SVG). A failing diagram shows the parser message and its source in place instead of a blank. The ESM build (`mermaid.esm.min.mjs` + chunks) is not vendored: `import` specifiers inside inline module scripts are not rewritten (ADR-0008 covers `<script src>` and `<link href>` only), so such documents still need the CDN. `static` mode (quarantine, Quick Look tier 3) leaves Mermaid as a code block, as the brief allows.

## ADR-0024 — File change detection needs the vnode watcher after all (2026-11-05, amends ADR-0013)
`presentedItemDidChange` fires only for coordinated writes; plain writes (`echo >>`, editors saving in place) and atomic saves (write temp, rename over the original) did not reach the document. `FileWatcher` adds a `DispatchSource` on the file descriptor (`write, extend, attrib, rename, delete, revoke`), debounced 250 ms, and re-opens the path after a rename so atomic saves keep being watched. Both paths funnel into `reloadIfChangedOnDisk`, which compares the bytes with the current data before replacing the text and asking the Read view to refresh, so duplicate notifications are harmless. XCTest covers in-place and rename saves against a real `ReadWebView`. M2 adds the unsaved-edits conflict banner on top of the same hook.

## ADR-0025 — Trust banner and popups are native decisions (2026-11-05)
The "Trust This Document" banner is an AppKit view stacked above the webview, so document content can neither imitate nor cover it. Trusting stores `path + quarantine value` in `UserDefaults` (`TrustStore`) and reloads the webview under the full policy; the file's bytes, attributes and modification date stay untouched (asserted). The same menu offers the per-document network toggle, also remembered per path. `javaScriptCanOpenWindowsAutomatically` is off, so script-initiated `window.open` is refused by WebKit before the UI delegate is consulted; user-initiated popups still reach `createWebViewWith`, which refuses them and hands http(s) targets to the default browser. A relative link to another `.md` file inside the document folder opens it as its own document instead of showing raw Markdown; other same-origin main-frame navigations are cancelled.

## ADR-0026 — Unlicense added to the shipped-code allowlist (2026-11-05, product owner)
The product owner accepted the Unlicense (an OSI-approved public-domain dedication with a fallback grant and no obligations) for shipped code, resolving the pending exception of ADR-0020 for `robust-predicates` inside `d3.min.js`. It is now on the allowlist next to MIT/BSD/Apache-2.0/ISC, so future Unlicense dependencies pass the check silently and appear only in THIRD_PARTY_NOTICES. This amends the brief's dependency rule; the `elkjs` (EPL-2.0) exception stays pending.

## ADR-0027 — EPL-2.0 accepted for the vendored Mermaid bundle only (2026-11-05, product owner)
`elkjs` (EPL-2.0 OR GPL-3.0-or-later, taken under EPL-2.0) is compiled unmodified into `mermaid.min.js` 12.x. The product owner accepted it as a named, per-package exception rather than adding EPL-2.0 to the allowlist: EPL is a weak file-level copyleft, and shipping the unmodified bundle with its notice in THIRD_PARTY_NOTICES meets its terms, but any new EPL dependency should be looked at on its own. If Inlay ever modifies ELK or Mermaid's bundle, revisit this entry.
