# Inlay — decisions (ADR log)

Short entries, newest at the bottom. Each: context, decision, consequence. Deviations from `docs/BRIEF.md` are proposed to the product owner before being logged as accepted.

ADR-0001 to ADR-0034 are accepted and in force. Entries tagged **proposed** (ADR-0035 onward, from the November 2026 review) are not in force: each waits for the product owner, and on acceptance the tag is replaced by the date and "product owner". A rejected proposal stays in the log with the reason. The review behind them is `docs/ARCHITECTURE.md` section 6.

## ADR-0001 — Read view renders client-side and replaces the page in place (2026-11-05)
The shell page at `mdview://<docId>/` embeds the document source as JSON; the read-view runtime renders it with md-render (browser build) and calls `document.open()/write()/close()` so document `<script>`/`<style>` run in page order like a navigated page and relative URLs resolve against the document folder. No fetch endpoint for the source exists, so `connect-src 'none'` stays literal. Refresh pushes new source via `evaluateJavaScript` (fallback `reload()`), scroll restored via `sessionStorage`. Fallback if `document.write` misbehaves in WKWebView: native renders through the JSC bundle and the webview navigates to the result.

## ADR-0002 — Both webviews load through the `mdview://` scheme handler (2026-11-05)
The editor webview also loads its page and document assets through the handler and traversal guard; only it gets the `WKScriptMessageHandlerWithReply` bridge. Web code receives the document base URL from `Host.openDocument`, never a hardcoded scheme, so Tauri can later map it to `http://mdview.localhost/…`. The `__inlay/` path prefix is reserved for runtime assets and shadows a same-named folder in the document directory.

## ADR-0003 — Byte preservation model (2026-11-05)
Swift keeps the original `Data`; the web core works on the losslessly decoded UTF-8 string plus `{bom, eol}`. All web offsets are UTF-16 string indices (remark positions), never bytes; bytes are produced only by re-encoding. Source mode first tries CodeMirror `lineSeparator` = dominant EOL so stray `\r`/`\n` survive as highlighted characters; if the mixed-EOL prototype shows glitches, fall back to normalized `\n` plus a per-line EOL table maintained through change sets. Non-UTF-8 files open read-only with a banner.

## ADR-0004 — WYSIWYG block model with per-block style sniffing (2026-11-05)
md-render's parse gives top-level blocks with offsets and inter-block gaps. Each block is round-tripped through Milkdown's parser + serializer with sniffed style options (bullet, emphasis/strong char, fence style, list indent, heading style, EOL) applied via a per-block remark instance, because `remarkStringifyOptionsCtx` is read once at editor creation. Mismatch ⇒ raw island atom holding the exact slice. Save: unchanged node ⇒ original slice; changed/new ⇒ serialized; islands ⇒ source attr; gaps and trailing newline preserved. remark versions are pinned shared between md-render and Milkdown and an mdast-equality test guards against phantom islands.

## ADR-0005 — Save pulls live editor content; native mirror only for crashes (2026-11-05)
`NSDocument.save(to:ofType:for:completionHandler:)` first requests content from the live editor (`callAsyncJavaScript`), then calls super; `data(ofType:)` returns that content. Autosave, Duplicate, Save As and Versions go through the same override. A debounced native last-known-good mirror is used only when the web content process has terminated or times out, and the user is warned. This keeps the brief's "never from a cached copy" while avoiding data loss on a WebContent crash.

## ADR-0006 — JavaScriptCore bundle constraints (2026-11-05)
esbuild IIFE, `platform: neutral`, no DOM. Shiki runs with `createHighlighterCoreSync` and the JavaScript regex engine (no WebAssembly dependence) over a curated grammar set, with a conservative regex target because the extension runs on the user's OS JavaScriptCore (macOS 14+). KaTeX via `renderToString`. Small polyfills (`TextEncoder`, `queueMicrotask`, `console`). `assetLoader` option lets Swift supply bytes for `inlineAssets`. The extension keeps one warm `JSContext`. A parity test requires identical `static` HTML from the browser and JSC builds for every fixture.

## ADR-0007 — Read view CSP, trust and network policy (2026-11-05)
Isolation: non-persistent store, no script message handlers, `WKUIDelegate` refuses `window.open`, navigation policy sends `http(s)` to the default browser and refuses `file:`, scheme handler `realpath`s every path and serves only the document folder. CSP is a response header (persists across `document.open`). With CDN = cdnjs.cloudflare.com, cdn.jsdelivr.net, unpkg.com (brief amendment): `default-src 'none'; script-src 'unsafe-inline' mdview: CDN; style-src 'unsafe-inline' mdview: CDN; font-src mdview: data: CDN; img-src mdview: data: blob: https:; media-src mdview: data: blob:; connect-src 'none'; frame-src 'none'; child-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`. Remote images are allowed by default (product owner decision 2026-11-05). Untrusted (quarantined, not yet trusted) documents get nonce-only `script-src` and static rendering. "Allow network" (per document, remembered per path) widens `connect-src`, `script-src`, `style-src`, `font-src` to `https:`. Trust is stored in app preferences keyed by path + quarantine xattr value; the file is never modified.

## ADR-0008 — Known-library URL rewriting (2026-11-05, brief amendment)
A rehype step rewrites Chart.js, ECharts, D3, Mermaid and KaTeX URLs on the three allowlisted CDNs (`<script src>` and `<link href>`, versioned or not) to bundled copies under a `vendorBaseURL` option (app: `mdview://<docId>/__inlay/vendor/…`; Quick Look Tier 2: `cid:` attachments). Rewrite only when the requested major version matches the bundled major or is unspecified; otherwise the CDN URL is left intact (still allowed by CSP). Vendored copies are shipped dependencies: license-checked and listed in THIRD_PARTY_NOTICES. The mapping table is data with per-URL-form unit tests.

## ADR-0009 — Custom-scheme origins (2026-11-05, brief amendment)
No web code assumes `https:`. `isTrustedOrigin(origin, baseURL)` in `host-api` handles `mdview://<docId>`, `http://mdview.localhost`, and WebKit's `"null"` origin; every `message` listener uses it. Unit-tested.

## ADR-0010 — No web→native channel from the Read view (2026-11-05)
Position for mode switching is pulled by native with `evaluateJavaScript`. Split-mode scroll sync is source→read only in v1; read→source would need a web→native path and can be added later through a bounded URL endpoint if wanted.

## ADR-0011 — `data-source-line` on raw HTML blocks (2026-11-05)
`rehype-raw` reparses raw HTML and drops positions. md-render injects `data-source-line` into the first start tag of each top-level raw HTML block before `rehype-raw` (skipping `<script>`, `<style>`, comments) so Split sync and mode switching stay accurate around embedded HTML.

## ADR-0012 — App is not App-Sandboxed (2026-11-05)
Distribution is Developer ID only (Mac App Store is a non-goal). Prompt-free access to sibling assets in the document folder is the blocker for sandboxing; hardened runtime stays on, which is all notarization needs. The Quick Look extension is sandboxed by the system; the M0 spike decides whether a scoped read-only exception is needed for sibling images.

## ADR-0013 — File change detection via NSFilePresenter first (2026-11-05)
NSDocument already conforms to `NSFilePresenter`; use `presentedItemDidChange` first, add a `DispatchSource` vnode watcher only if uncoordinated writes are missed, and deduplicate notifications by content hash.

## ADR-0019 — App icon rendered from SVG masters through CoreSVG (2026-11-05)
The app icon, mark and glyphs live as SVG masters in `design/icon/`; `scripts/render-icons.sh` renders the Xcode `AppIcon.appiconset` (16 to 1024 px, with a simplified cut for 16 and 32 px) and the web favicons, and the PNGs are committed so a checkout builds without the script. Rendering uses a 30-line AppKit program (`scripts/icons/svg2png.swift`, NSImage + CoreSVG on a transparent bitmap) instead of a Node or Homebrew dependency: `rsvg-convert` is not installed by default, ImageMagick's built-in SVG renderer drops gradients, and `qlmanage` thumbnails are flattened on white. CoreSVG does not support `feMerge`, so the icon's drop shadow is a separate blurred rectangle. The catalog is a plain `appiconset` rather than a macOS 26 `.icon` bundle because the deployment target is macOS 14; Liquid Glass wraps the legacy icon on newer systems, and a `.icon` variant can be added later without changing the masters.

## ADR-0021 — md-render output contract and highlighting strategy (2026-11-05)
`render()` returns body-only HTML; the embedding page (Read view, Quick Look, export) owns `<html data-theme>` and includes `THEME_CSS`, so one theme follows `prefers-color-scheme` unless overridden. Mode behaviour: `full` keeps the document verbatim (optionally stripping scripts and inline handlers with `allowScripts: false`); `static` and `sanitized` replace every `<script>` with a placeholder and sanitize with a schema that keeps SVG, MathML, inline styles, classes, ids and `data-*` (no clobber prefix, so footnote links work); `sanitized` also drops `<style>`. KaTeX and Shiki run after sanitizing because their output is ours. Highlighting is pluggable (`CodeHighlighter`): the JavaScriptCore build highlights synchronously with 40 bundled grammars (4.3 MB IIFE); the browser first paints unhighlighted `<pre><code class="language-x">` for an instant first render, then read-view lazily imports only the grammars in `meta.codeLanguages` and upgrades the blocks in place with `highlightToHtml`. Both builds use the JavaScript regex engine with `target: 'ES2018', forgiving: true` so output is byte-identical (the parity test compares every fixture in every mode). Shiki emits dual-theme CSS variables; `light-dark()` is avoided because macOS 14's WebKit predates it. Raw HTML blocks get `data-source-line` injected as the first attribute of their start tag (ADR-0011); `integrity`/`crossorigin` are dropped from rewritten CDN tags because the hashes were computed for the CDN file.

## ADR-0022 — Read view runtime: in-place page replacement, reload-based refresh, dev view route (2026-11-05)
The runtime renders the embedded source and replaces the shell with `document.open()/write()/close()` as planned in ADR-0001; Playwright (Chromium, WebKit) and the WKWebView XCTest confirm the CSP response header survives the replacement and that document `<style>`/`<script>` run at page level. **Refresh reloads instead of re-writing:** `inlayReadView.refresh()` stores the top source line in `sessionStorage` and calls `location.reload()`; the scheme handler re-embeds the live source and the runtime restores the position by source line (falling back to pixels). A second `document.write` in the same Window would leave the previous render's timers and globals alive, so a reload is both simpler and safer; Split mode (M2) can revisit this if reload latency matters. Runtime assets (vendor copies, lazy grammars) resolve from Vite's `BASE_URL` (`/__inlay/`, the reserved prefix of ADR-0002) against the page URL, so no scheme is hardcoded: `mdview://<docId>/__inlay/…` in the app, `http://localhost/__inlay/…` in dev. The browser dev server mirrors the app faithfully: `/__fixtures/view/<file>.md` serves the same shell with the fixture embedded and the same CSP (built by `packages/read-view/src/csp.ts`, kept in sync with the Swift builder by unit tests on both sides), and other paths under `/__fixtures/view/` serve files from the fixture folder behind the same traversal guard, so Playwright exercises the real policy. The dev bar is part of the rendered page only when the payload carries `dev`.

## ADR-0023 — Mermaid via the vendored UMD bundle, re-rendered on theme change (2026-11-05)
In `full` mode md-render emits `<pre class="mermaid">source</pre>`; the runtime injects the vendored `mermaid.min.js` (the same file CDN rewriting points documents at, so one copy serves both) only when the document has such blocks, then calls `mermaid.run` per node with `securityLevel: 'strict'`. Each node keeps its source in `data-inlay-mermaid-src` so diagrams re-render when `setTheme` or the system appearance changes (Mermaid bakes the theme into the SVG). A failing diagram shows the parser message and its source in place instead of a blank. The ESM build (`mermaid.esm.min.mjs` + chunks) is not vendored: `import` specifiers inside inline module scripts are not rewritten (ADR-0008 covers `<script src>` and `<link href>` only), so such documents still need the CDN. `static` mode (quarantine, Quick Look tier 3) leaves Mermaid as a code block, as the brief allows.

## ADR-0024 — File change detection needs the vnode watcher after all (2026-11-05, amends ADR-0013)
`presentedItemDidChange` fires only for coordinated writes; plain writes (`echo >>`, editors saving in place) and atomic saves (write temp, rename over the original) did not reach the document. `FileWatcher` adds a `DispatchSource` on the file descriptor (`write, extend, attrib, rename, delete, revoke`), debounced 250 ms, and re-opens the path after a rename so atomic saves keep being watched. Both paths funnel into `reloadIfChangedOnDisk`, which compares the bytes with the current data before replacing the text and asking the Read view to refresh, so duplicate notifications are harmless. XCTest covers in-place and rename saves against a real `ReadWebView`. M2 adds the unsaved-edits conflict banner on top of the same hook.

## ADR-0025 — Trust banner and popups are native decisions (2026-11-05)
The "Trust This Document" banner is an AppKit view stacked above the webview, so document content can neither imitate nor cover it. Trusting stores `path + quarantine value` in `UserDefaults` (`TrustStore`) and reloads the webview under the full policy; the file's bytes, attributes and modification date stay untouched (asserted). The same menu offers the per-document network toggle, also remembered per path. `javaScriptCanOpenWindowsAutomatically` is off, so script-initiated `window.open` is refused by WebKit before the UI delegate is consulted; user-initiated popups still reach `createWebViewWith`, which refuses them and hands http(s) targets to the default browser. A relative link to another `.md` file inside the document folder opens it as its own document instead of showing raw Markdown; other same-origin main-frame navigations are cancelled.

## ADR-0028 — Mixed line endings: CodeMirror `lineSeparator` = dominant EOL, text kept verbatim (2026-11-05, M2)
The prototype planned in ADR-0003 confirmed approach A for every fixture (`packages/editor/src/eol-prototype.test.ts`): Source mode creates its `EditorState` from the decoded text with `EditorState.lineSeparator` set to the dominant EOL (`detectEol`), so a stray `\n` in a CRLF file (or `\r` anywhere) stays a character inside its line, `highlightSpecialChars` shows it as ␊/␍, Enter inserts `state.lineBreak`, and `getText()` (= `state.sliceDoc()`, which joins with the facet's separator; `Text.toString()` joins with "\n" and is never used) reproduces the input byte for byte through edits. Two glitches were found and handled: text pasted or dropped in carries the clipboard's endings, so `clipboardInputFilter` rewrites them to the document's (and `clipboardOutputFilter` puts "\n" on the pasteboard for other apps); and CodeMirror counts every line break as one position, so in CRLF documents editor offsets are not UTF-16 indices into the text — `offsetToStringIndex`/`stringIndexToOffset` convert, and M3's block splicing must use them. Line numbers also diverge after a stray ending because remark breaks on `\r\n`, `\n` and `\r` alike: `buildLineMap` (identity for single-EOL files) maps editor lines ↔ source lines for scroll sync and mode switching. The fallback (normalized "\n" plus a per-line EOL table maintained through change sets) is not needed. Non-UTF-8 files open with `EditorState.readOnly`.

## ADR-0029 — Editor page and the WebKit Host bridge protocol (2026-11-05, M2)
The editor is its own Vite page (`packages/editor`, base `/__inlay/editor/`) served by the same `mdview://` handler as the Read view under the reserved prefix of ADR-0002, so one handler, one traversal guard and one MIME table cover both webviews. Unlike the Read shell the editor page embeds nothing: the text arrives through `Host.openDocument()`, and the page runs only our bundle (document text is data inside CodeMirror), so its CSP needs no `'unsafe-inline'` for scripts. The adapter (`packages/host-api/src/webkit.ts`, the only file allowed to touch `window.webkit`; the audit test now asserts exactly that file) posts `{ method, args }` to the reply handler named `inlay` and receives the result as the promise value; fire-and-forget calls (`setDirty`, `requestMode`, `notifyContentChanged`, `reportPosition`) still travel the same way so native errors surface in the console. Native → web goes through `window.inlayWebKitHost`: `requestContent()` (the live text for saves and the crash mirror, ADR-0005) and `emit(event, payload)` for Host events, including the new `documentSaved` event which tells the editor that the text it last handed out is the clean baseline (dirty state is `!doc.eq(savedDoc)`, so undoing back to the saved text clears it). `Host.reportPosition` is new: the editor pushes its top source line and cursor (debounced) for Split-mode sync and the pane header; native never has to poll it. In the browser the page uses `MockHost` with `?fixture=<file>` fetched from the dev server, which is what Playwright exercises in Chromium and WebKit.

## ADR-0030 — Live text is pulled at the save entry points; own writes are not external changes; conflicts never overwrite (2026-11-05, M2; amends ADR-0005)
ADR-0005 planned to await the editor inside `save(to:ofType:for:completionHandler:)`. That deadlocks: NSDocument calls that method from inside its file-access/activity queue (autosave, Duplicate, Versions), and calling `super` from a later turn queues a second file access behind the first, which only ends when ours completes (found by the XCTest for `autosave(withImplicitCancellability:)`, which never called back). So the pull moved in front of the queue: `save(_:)`, `saveAs(_:)`, `saveTo(_:)`, `duplicate(_:)` and `canClose(withDelegate:…)` (the "Save changes?" path) await the editor's live text (`EditorWebView.requestContent()` through `window.inlayWebKitHost`, 3 s race that does not wait for a dead web process) and then call `super`; `save(to:…)` stays synchronous and only does bookkeeping, and `data(ofType:)` re-encodes the document's text plus BOM. The text pulled on every debounced `notifyContentChanged` is the mirror, at most ~0.5 s behind the editor; periodic autosave, Versions and the programmatic `duplicate()` write it, user-initiated saves write the live text exactly. When a user-initiated pull fails the save still succeeds from the mirror, `lastSaveUsedMirror` is set and the window warns once. `autosavesInPlace` is on (Versions, Rename/Move/Duplicate in the title bar); autosave does not touch the editor's dirty baseline, only Save and Save As emit `documentSaved`. Because the vnode watcher sees our own writes, the document records the bytes it just wrote as `fileData` in the save completion, so `reloadIfChangedOnDisk` finds nothing to do after a save or autosave. When the disk bytes differ and the document is edited, nothing is replaced: `hasConflict` goes up (native banner outside the webviews) with two choices — reload from disk (drops the edits, clears the change count, both views reload through `fileChanged`) or keep editing, in which case NSDocument's own modification-date check still asks before an explicit save overwrites and `checkAutosavingSafety` holds autosave back until then. Undecodable files are read-only in the editor and always write their original bytes.

## ADR-0031 — Modes are native pane visibility; Split re-renders by reload and syncs source → read (2026-11-05, M2)
Read, Source and Split are states of one window (`ViewMode`, remembered in `UserDefaults`): an `NSSplitViewController` holds the editor pane and the Read pane as `NSSplitViewItem`s, and a mode only collapses items, so both webviews stay loaded and switching is instant. (A bare `NSSplitView` inside the window's vertical `NSStackView` was tried first and only ever got its fitting width — the pane headers' — so the split controller's view is pinned with explicit constraints below a stack that holds just the banners.) Position carries over by source line (ADR-0010): the view that was showing is asked for its top line (`inlayEditor.getPosition()` / `inlayReadView.getPosition()`), and the view being shown scrolls there; the editor also puts its cursor on that line. In Split mode the editor's debounced `reportPosition` drives `inlayReadView.scrollToSourceLine` directly (no polling), the Source pane header shows "Ln n, Col m", and the divider carries a verdigris marker at the editor's relative position. Edits reach the Read pane through the mirror: the bridge's debounced content pull updates the document's live text, the window calls `ReadWebView.refreshDocument()`, the runtime reloads from the live source (ADR-0022) and `onPageLoaded` re-applies the synced line, which keeps the reload-based refresh usable for Split without the in-place re-render ADR-0022 held in reserve (measured on the 10k-line fixture the edit → re-rendered heading round trip is well under a second in XCTest; revisit if typing latency ever shows in Split). The pane headers, the trust and conflict banners and the toolbar's Read / Edit / Source / Split control are AppKit, so document content can neither imitate nor cover them; "Edit" (WYSIWYG) stays disabled until M3. With `autosavesInPlace` the File menu follows the platform: Duplicate (⇧⌘S) with Save As as its ⌥ alternate, Rename, Move To and Revert To → Browse All Versions.

## ADR-0032 — WYSIWYG blocks are exact, restyled or islands; verification is deferred (2026-11-06, M3; refines ADR-0004)
The loader (`packages/editor/src/wysiwyg/loader.ts`) parses the document once with the editor's remark (the same remark-parse, remark-gfm, remark-math and remark-frontmatter versions as md-render, pinned through pnpm overrides) and turns every top-level block into a ProseMirror node. Raw HTML, front matter and `::`/`:::` directive paragraphs are islands outright; any block the schema cannot represent becomes one too (`unsupported`). The rest are round-tripped ProseMirror → mdast → Markdown with a style sniffed from their own slice (`style.ts`: bullet and ordered markers, list indentation, fences vs indented code, closing hashes, setext, thematic-break shape, title quotes, table padding, a tight list after a paragraph) plus a few variants for what cannot be sniffed. Markers that vary inside one block travel on the nodes themselves, like Milkdown's emphasis markers: hard breaks record "two spaces" or "backslash", links record whether they were bare autolink literals (`remarkInlayMarkers`), so one paragraph can mix them and still reproduce. A block whose serialization equals its slice is `exact`. When the bytes differ but the plain parser yields the same mdast (hand-padded tables, trimmed trailing whitespace, `\#` escapes, a bare `\n` inside a CRLF paragraph) the block is `restyled`: it is edited in WYSIWYG like any other, an unchanged restyled block still saves as its original slice, and only once the user edits it does it take the canonical form, confined to that block. This is the reading of the brief's round-trip rule that makes "zero islands on pure-GFM fixtures" hold (every table would otherwise be an island) while keeping byte identity for everything untouched; the island ratio counts true islands only, and `stats` reports exact/restyled/islands separately. Milkdown plugins that rewrite documents are removed before the editor is created: remark-inline-links (would drop reference definitions; `definition`, `link_reference` and `image_reference` nodes replace it), the trailing paragraph, heading-id sync, Crepe's LaTeX feature (turns `$$` math into a `LaTeX` fence; own `math_block`/`math_inline` nodes instead) and Crepe's image block (rewrites alt text). Milkdown's `text` handler is replaced because it emits any text ending in whitespace unescaped, which lost `\$5`. Verification (serialize, compare, fall back to mdast equality) costs about 0.3 ms per block, so it runs after the view is up in idle chunks (`verify(budgetMs)`); byte identity never depends on it because an unchanged block always saves as its slice, and the only late outcome, a `mismatch` island, is applied as a node swap when the block is still untouched.

## ADR-0033 — One editor page hosts Source and WYSIWYG; the host asks for a mode, the page switches (2026-11-06, M3)
WYSIWYG lives in the same editor webview as Source mode (`packages/editor/src/page.ts`): native keeps one bridge, one CSP and one `window.inlayEditor`, and a mode switch never reloads a page. The page owns the save baseline (`savedText`, what the host last opened or wrote) and hands the live text from one editor to the other on a switch, mapping the caret by UTF-16 index into that text (CodeMirror offsets go through `offsetToStringIndex`, ADR-0028; WYSIWYG positions go through the splice segments) and the viewport by source line; the receiving editor is only reloaded when its text differs, so undo history survives a round trip without edits. `DocumentInfo.mode` is a new optional field: the host says which mode to start in (`EditorBridge` sends the window's `ViewMode`), later switches arrive as `modeRequested`; in the browser `?mode=wysiwyg` does the same. The Milkdown bundle (Crepe, Vue, ProseMirror, the block model) is loaded on demand, so Source mode keeps its 97 kB bundle. Two Milkdown defaults were replaced for the 10k-line budget: the listener plugin serializes the whole document to Markdown when the state is created (200 ms) and debounces updates by 200 ms, so a plain ProseMirror view plugin reports changes instead; Crepe's list item mounts a Vue app per item (two thousand in the fixture), so `list-item-view.ts` renders the marker and task checkbox with plain DOM. Crepe's virtual cursor is off (the native caret handles Home/End and IME better). Measured in Chromium: parse and block building ~420 ms, state ~15 ms, view ~260 ms (Crepe's table block is a Vue app per table, 158 of them), total under 1 s in both Chromium and WebKit; block verification runs afterwards in 12 ms slices.

## ADR-0034 — IME: input rules never run on composed text; large documents open in Source (2026-11-06, M3)
ProseMirror lets the browser own an IME composition and reads the committed text back, which is what Vietnamese Telex/VNI and CJK input need; CodeMirror does the same in Source mode. Milkdown's input rules (`#` → heading, `**` → strong, `` ` `` → code, …) run on typed text and, in Milkdown's `customInputRules`, once more on `compositionend` against the text before the caret, so a composed `*` or `#` could restructure a paragraph the moment the IME commits. `composition.ts` wraps that plugin when the editor state is built: rules keep running for typed text and for Enter, never while `view.composing` and never on `compositionend`. Playwright drives real compositions through CDP in Chromium (`Input.imeSetComposition` + `Input.insertText`): a Telex-style `chao` → `chào` lands once, composed `**bold**` stays literal while typed `**real**` becomes strong, hiragana → kanji replaces the marked text, undo removes one commit; WebKit has no composition API in Playwright, so `docs/IME-CHECKLIST.md` gains a WYSIWYG section for the release build. The large-document safety net from ADR-0016 lives in the page: above 50k lines or 5 MB a document asked to open in WYSIWYG opens in Source instead, tells native (`requestMode('source')`) so the toolbar agrees, and shows a banner with "Open in WYSIWYG anyway"; the threshold is lowered in tests with `?safetyLines=`. Two Crepe features stay off for the 10k-line budget and are follow-ups: the table block (a Vue app per table; plain prosemirror-tables editing and Tab navigation remain) and, until a lighter design exists, nothing else; KaTeX and sanitized island previews render lazily when they near the viewport (`lazy.ts`).

## ADR-0035 — Own the editor chrome; shrink the dependence on Crepe (2026-11-12, proposed)
M3 already replaced or switched off most of Crepe's node-level features for the 10k-line budget and for byte fidelity: the list item view, the table block, the image block, the LaTeX feature, the listener and the virtual cursor (ADR-0032 to ADR-0034). What remains of Crepe is chrome (toolbar, menus, placeholder, code block) built on Vue. Proposal: keep Milkdown's kit and ProseMirror, keep the schema, loader, transformer and splice (ours), and replace the remaining Crepe pieces with plain ProseMirror plugins and DOM as each one is touched: table handles first, then the toolbar and the slash menu. No rewrite milestone; the brief already names raw ProseMirror as the exit. Consequence: Vue leaves the editor bundle, per-node cost stays flat, and upstream changes to Crepe stop being a risk to the block model.

## ADR-0036 — The Read view patches changed blocks; a reload only when scripts change (2026-11-12, proposed; amends ADR-0022 for Split)
ADR-0022 refreshes by reloading because a second `document.write` would leave the previous render's timers and globals alive. In Split that reload happens on every edit burst: every script re-runs, charts redraw, widgets lose their state (`docs/ARCHITECTURE.md` P1). Proposal: the runtime keeps, per rendered top-level block, its source range and a hash of its HTML. On refresh it renders the new source, and if the set of `<script>` and `<style>` blocks and their order is unchanged it replaces only the block elements whose hash differs, re-running lazy highlighting and Mermaid for those nodes; otherwise it reloads as today. The position is kept by source line in both cases. A prose edit then costs a DOM patch; a script edit costs what it costs now. md-render already emits `data-source-line`; the block hash is new metadata, identical in the JavaScriptCore build.

## ADR-0037 — Read to Source through one bounded navigation (2026-11-12, proposed; extends ADR-0010)
ADR-0010 left read-to-source sync for later because the Read view has no channel to native code. Proposal: a double-click on a block in the Read view navigates to `mdview://<docId>/__inlay/goto?line=<n>`. The navigation policy cancels it and, only if a real mouse event reached the webview in the last second, switches to the editor at that source line. The payload is one bounded integer, validated natively; a document script that forges it can at most scroll the user's own editor. No script message handler is added, so the rule "the Read view has no handlers" stands unchanged.

## ADR-0038 — One file-access layer, ready for the App Sandbox (2026-11-12, proposed; amends ADR-0012)
ADR-0012 keeps the app unsandboxed because sibling assets must load without a prompt. That still holds for the direct build. Proposal: route every file read and write in Swift (document bytes, sibling assets, linked Markdown, pasted images, the trust store's identities) through one `DocumentAccess` type that can hold security-scoped bookmarks. The direct build uses it without a sandbox; a second build configuration turns the sandbox on and asks once per folder for access. This is what a Mac App Store or Setapp-store edition needs, and it is defence in depth for an app that runs document scripts. The Mac App Store is a v1 non-goal in the brief; shipping there needs a brief amendment (`docs/BRIEF-AMENDMENTS.md`, A3).

## ADR-0039 — Internal extension points before any plugin system (2026-11-12, proposed)
Present, the export suite, the snippet gallery and the workspace all add commands, exporters, panes and insertable snippets. Proposal: four small registries in the web core (commands, exporters, panes, snippet providers), each mirrored by a `Host` capability where native help is needed (a save panel, a menu item). First-party features register through them, and so do the closed Pro modules (ADR-0040). They are internal: no stability promise, no third-party loading. A public plugin system stays a non-goal until these have carried Pro for a year.

## ADR-0040 — Pro lives outside the public repository; licences are verified offline (2026-11-12, proposed; product owner decision D1 to D3)
If the product owner chooses the open-core model of `docs/MONETIZATION.md`: Pro modules (web bundles and a Swift package) live in a private repository and are added by the official release workflow; the public repository builds a complete app without them. A licence is a small file signed with Ed25519, carrying product, edition, licensee, issue date, updates-until date and seats; the public key ships in the app and CryptoKit verifies it on the Mac. No account, no activation server, no call home; a build unlocks Pro when its release date is on or before the licence's updates-until date. Free features never consult a licence. Apache-2.0 permits the combination and the DCO needs no change, because community code is never relicensed.

## ADR-0041 — Trust follows the file and the folder; permissions in one native popover (2026-11-12, proposed; amends ADR-0007 and ADR-0025)
Trust and "Allow network" are keyed by path today, so a rename loses them and a different file at the same path inherits them (`docs/ARCHITECTURE.md` S7). Proposal: key both by file identity (a bookmark, falling back to volume and file id) together with the quarantine value; allow trusting a folder once, which covers the files in it; show scripts, network and remote images, and where each permission came from, in one native popover on the toolbar; and read managed preferences so an organization can force scripts off, fix the CDN list and disable "Allow network". All of it stays native UI above the webviews.

## ADR-0042 — No telemetry; diagnostics only on a click (2026-11-12, proposed)
The app has no logging beyond the Quick Look stub and no way to learn about a crash. Proposal: `os.Logger` throughout the shell; MetricKit crash and hang reports kept on the Mac; a Help menu item that shows the report and sends it only when the user clicks. No analytics, no usage events, no identifiers. Adoption is measured outside the app: downloads, update-feed requests counted in aggregate, public Homebrew counts.

## ADR-0043 — English and Vietnamese first; web strings arrive through Host (2026-11-12, proposed)
Every user-facing string is a literal today. Proposal: a String Catalog for the Swift shell; one string table per web package, loaded for the locale that `Host` reports, with English as the fallback bundled in the page; Vietnamese as the first translation, because Vietnamese input is a stated priority of the brief. Dates, numbers and word counts use `Intl`. Document content is never translated or touched.

## ADR-0044 — A document that runs scripts gets no way out (2026-11-12, proposed; amends ADR-0007 and ADR-0016)
The review found three ways for a script in a trusted, never-quarantined document to send data out or read more than it should (`docs/ARCHITECTURE.md` S1 to S4): remote images are allowed by default, so any value can leave in an image URL; every `http(s)` and `mailto` navigation opens the default browser without a click; and the served root is the document's whole parent folder. Proposal: (1) when scripts run and the user has not allowed network, `img-src`, `media-src` and `font-src` drop `https:`; documents without scripts keep remote images, so badges and pictures still load in ordinary Markdown. (2) An external open needs a real user event: native records the last mouse or key event delivered to the webview and honours an external navigation only within a second of it. (3) The handler refuses hidden files and folders, serves only an allowlist of types (images, media, fonts, styles, scripts, Markdown), and refuses to serve sibling files at all when the document's folder is the home folder or a volume root. (4) Quarantine is re-read on every reload from disk and carried to duplicates and untitled copies. (5) `alert`, `confirm` and `prompt` become a sheet on the document's window with "stop showing dialogs from this document". Point (1) changes the product owner's decision of 2026-11-05 on remote images, so it needs explicit approval.

## ADR-0045 — Native owns dirty state; a save names the text it wrote (2026-11-12, proposed; amends ADR-0029 and ADR-0030)
The editor reports dirty state only when it flips, against a baseline that moves only on `documentSaved`, which autosave does not emit. After the first autosave `NSDocument` is clean while the editor still counts itself dirty and says nothing more, so later edits are never announced (`docs/ARCHITECTURE.md` C1, C2). Proposal: every `notifyContentChanged` marks the document edited (`updateChangeCount(.changeDone)`); the editor's own flag only drives its UI. `provideContent` returns the text with a monotonically increasing token; every successful write, autosave included, emits `documentSaved` with the token of the text that reached the disk, and the editor moves its baseline only if that token is the one it handed out. The first task is the test that shows the failure: edit, autosave, edit, close, reopen.

## ADR-0046 — App assets get their own origin; the handler knows who is asking (2026-11-12, proposed; amends ADR-0002)
Runtime assets, the editor page and document-folder files share the origin `mdview://<docId>`, and the editor's CSP is `script-src mdview:`. A file in the document's folder is therefore an allowed script source on the page that holds the native bridge; only the island sanitizer stands in the way (`docs/ARCHITECTURE.md` S5). Proposal: serve everything under the reserved prefix from a separate host (`mdview://app/…`, mapped to `http://app.mdview.localhost` on other shells), give the editor page a CSP that names only that host for scripts, give each webview its own handler instance bound to its document and role, and refuse the editor route to the Read webview. Base URLs still come from `Host`, so web code does not change shape. ADR-0002's "one handler, one guard, one MIME table" stays true in code; what changes is the origin layout.

## ADR-0047 — One version, tags and a tag-driven release (2026-11-12, proposed)
The repository carries three unrelated versions (`0.0.0` in `package.json`, `0.1.0` in `project.yml`, `0.1.0-m1` in md-render), no tags and no changelog. Proposal: the root `package.json` version is the only source; a script writes `MARKETING_VERSION` and md-render's constant from it and CI fails when they differ; the build number is the commit count on `main`. Semantic versioning from 1.0; betas as `0.9.x`. `CHANGELOG.md` is written for users, one section per release. A `release.yml` workflow triggered by a `vX.Y.Z` tag archives, signs with the Developer ID (G2) certificate, notarizes, staples, builds the disk image, signs the Sparkle archive and drafts the GitHub Release. Signing secrets are the product owner's to provide.

## ADR-0048 — The documentation set and who owns what (2026-11-12)
The review added product, architecture, testing, checklist and business documents beside the brief, the plan and this log. To keep them from drifting: `BRIEF.md` is the product owner's and is never edited, changes are proposed in `BRIEF-AMENDMENTS.md`; `PRODUCT.md` says what the app is and does; `ARCHITECTURE.md` how it is built and what the last review found; `ROADMAP.md` which release carries what; `MONETIZATION.md` the business model; `PLAN.md` the task lists and their state; `TESTING.md` the test strategy and inventory; `CHECKLIST.md` the gates and manual checks; `HANDOVER.md` the state for the next session; `DECISIONS.md` why. A fact lives in one of them and the others link to it: prices only in MONETIZATION, test counts only in TESTING, task state only in PLAN.

## ADR-0049 — Positioning: reading first, "Markdown that runs" (2026-11-12, proposed)
Proposal: lead with the two guarantees (everything renders and nothing escapes; the file on disk is sacred) and with the reader of generated documents as the entry audience, because Markdown written by AI tools now carries diagrams, SVG and HTML and has no safe native viewer that also edits losslessly. WYSIWYG stays the primary editing mode, as the brief says; the order of polish is Quick Look, Read, then the editors. Consequences: a welcome document and a browser playground matter more than editor features for the launch; "Open documents in" becomes a visible setting; Quick Look is how people meet Inlay, not what is sold (`docs/PRODUCT.md`, `docs/MONETIZATION.md` section 2).

## ADR-0050 — Quick Look after macOS 27.3: prove precedence first, sell rich rendering (2026-11-12, proposed; amends the M4 plan)
The macOS 27.3 beta renders basic Markdown in Quick Look by itself, and on iOS 27 third-party data-based Markdown preview extensions are reported as no longer invoked. Proposal: M4 starts with a one-day spike on the 27.3 beta, with the existing stub extension, to establish whether a third-party extension still takes precedence for `net.daringfireball.markdown`; the result is recorded here before the tiers are built. If it does, M4 proceeds as in the brief, and its value is what the system preview lacks: SVG, math, Mermaid, charts, local images. If it does not, Tier 1 is still built for macOS 14 to 26, feedback is filed with Apple, and the app's own "open and read" path carries discovery. Either way `RenderEngine.RenderOptions` gains the asset loader the tiers need, and the extension gets tests.

## ADR-0051 — Business model: open core (2026-11-12, proposed; product owner decision D1)
Proposal, detailed in `docs/MONETIZATION.md`: the app stays free and Apache-2.0, including everything in the brief and every safety feature; a paid Pro licence for the official build unlocks features for producing deliverables, starting with release 1.2; store channels and team licences follow the sandboxed build; a hosted service is considered only behind a demand gate. Nothing ships paid before the product owner decides D1 to D5. Two rules are meant to be published as a pledge: a feature that ships free is never moved to paid, and safety and fidelity are never sold.

## ADR-0052 — A gap belongs to a pair of neighbours; the splice checks its own result (2026-11-12, proposed; amends ADR-0004 and ADR-0032)
The splice writes a block that kept its bytes with the gap that preceded it in the original text, whatever now stands before it. Deleting or retyping the block between two others can therefore join them: `A`, blank line, `# H`, newline, `B` without the heading is saved as one paragraph (`docs/ARCHITECTURE.md` C9). Proposal: a kept block keeps its original gap only when the block emitted before it is its original predecessor, also kept; in every other case the gap is a blank line in the document's line ending. After assembling, the splice parses the result with the plain parser and compares the sequence of top-level block types with the editor's document; on a mismatch it falls back to serializing the affected run with blank-line gaps and reports it in `stats`. Two related rules: a block still pending verification (ADR-0032) is verified synchronously before its first edit is applied, and mode switches are queued and read the outgoing editor's text after every await (C10, C11). Each starts with the failing test.

## ADR-0053 — Island previews are isolated from the page that holds the bridge (2026-11-12, proposed; amends ADR-0021)
The editor page inserts md-render's `sanitized` output with `innerHTML`. Script execution is prevented by the page's CSP rather than by the schema, which leaves id and name clobbering on, treats `xlink:href` as unrestricted, allows any `style` and allows SMIL (`docs/ARCHITECTURE.md` S11). Proposal: previews render in a closed shadow root with `contain: layout paint style` so nothing can cover or restyle the editor; the schema restores the clobber prefix for `id` and `name` outside footnotes, drops SMIL elements and `attributeName`, restricts `href` and `xlink:href` on `use` and `image` to same-document fragments and `data:` images, and limits `style` to a property allowlist; a hostile-markup corpus is added to the fixtures and asserted in all sanitizing modes. Quick Look pages get a CSP `<meta>` in every tier, `script-src 'none'` unless Tier 2 is on.

## ADR-0054 — Host carries requests in both directions; one origin per document on every shell (2026-11-12, proposed; amends ADR-0029)
Native drives the pages by evaluating JavaScript against `window.inlayEditor`, `window.inlayReadView` and `inlayWebKitHost` and reading the result. That path is outside `Host`, is typed on neither side, and has no equivalent in a shell whose script evaluation returns nothing. Proposal: the bridge protocol of ADR-0029 gains native-to-web requests with ids and replies (`requestContent`, `getPosition`, `scrollToSourceLine`, `setTheme`, `setMode`), declared once in `packages/host-api` and generated or mirrored for Swift; the Read view keeps having no handlers, so its few native-to-web calls stay as evaluated functions but are declared in the same file and covered by the same contract test. For other shells the document id moves from the path to the host (`<docId>.mdview.localhost`), so each document keeps its own origin as it has on the Mac; `isTrustedOrigin` and its tests change with it. `Host` methods nobody calls are removed or put to use when the settings page and export arrive.
